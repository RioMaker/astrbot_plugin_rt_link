# 公共 TJA 分析库

每份单人鬼/里谱面只保存一套公共分析结果，所有玩家共用。原始 TJA 按字节保存在 ZIP 中；整曲特征和逐小节参数按谱面 gzip 压缩后保存在 SQLite。内部公共谱面查询不解析原谱、不访问菌菌 API、不要求绑定账号或已有成绩。v0.17.0 起该完整分析接口不再注册为 AI 工具；AI 的 `query_song_brief` 读取内置评级谱面配置摘要，玩家成绩部分按需同步。

不生成曲线图片，不重训或修改 AI 定数，不预测精度、全连率或过关概率。

## 数据目录与运行方式

部署位置是 AstrBot 的 `data/plugin_data/astrbot_plugin_rt_link/chart_library/`，通过 `StarTools.get_data_dir` 定位。插件代码与谱面数据独立保存；`resource/chart-library-20261014.zip` 随 Git 仓库一起提供，启动时默认后台安装 `resource/chart_library.release.json` 固定的版本，首次调用也会检查初始化状态。默认安装全程读取内置包，不需要请求 Release 或其他下载地址。安装成功后从本地查询，重启不会重复下载。没有分析库时，新工具返回安装进度或明确失败原因，原查分和 Rating 功能照常运行。

安装器先校验内置包的固定大小和 SHA-256；显式配置镜像时才使用有大小限制的流式下载。随后限制解压路径与总体积，再校验内部文件、歌曲目录版本和 SQLite 完整性，最后原子切换指针。并发查询共用一次安装任务。下载失败保留当前版本和备份，5 分钟冷却后下次查询可重试；插件卸载会取消下载并清理本次暂存文件。已有兼容旧库时，更新期间仍能查询旧库，结果保留实际 `buildId`。

| 配置 / 命令 | 用途 |
| --- | --- |
| `chart_library_auto_install` | 默认 `true`，后台安装；关闭后仍可查询已有库 |
| `chart_library_download_url` | 默认留空使用内置 ZIP；可指定 HTTPS 镜像覆盖本地来源，文件字节必须与固定包一致 |
| `chart_library_quota_mb` | 默认 512 MiB，包含所有旧版本及下载/解压暂存空间，独立于玩家成绩配额 |
| `/rtlink library` | 所有用户可查看本地库和安装状态 |
| `/rtlink library retry` | 仅管理员可绕过冷却或关闭开关，重试安装及损坏版本修复 |

单次查询最多等待初始化 2 秒，尚未完成则返回状态供稍后重试，不取消后台任务。AstrBot 获取插件仓库时需要网络；插件和依赖已安装后，默认分析库初始化及查询均不需要网络。状态接口不输出镜像地址，避免暴露地址中的访问参数。安装时除下载和解压空间外，还预留 8 MiB 配额空间及 128 MiB 磁盘空间；同版本修复也先保存损坏目录，不自动删除旧版本。

## 从 Git 仓库安装

本版本（v0.15.1）把数据包作为普通 Git 文件提交，**不使用 Git LFS，也不需要单独创建 GitHub Release**。维护者推送包含本功能的 `main` 后，在 AstrBot 使用仓库地址安装或更新 RTLink，保持自动安装开启、镜像地址留空。插件会后台校验并解压内置包到持久化目录，`/rtlink library` 显示 `ready` 后即可查询。

仓库地址：`https://github.com/RioMaker/astrbot_plugin_rt_link`。首次下载源码会多传输约 27.7 MiB；插件目录保留压缩包，数据目录展开约 32.34 MiB，二者合计约 60 MiB，Git 对象及旧版本另计。后续谱面数据变更会产生新的 Git 历史对象。

当前数据版 `2026-10-15.1`，内置包沿用文件名 `resource/chart-library-20261014.zip`，为 **29,046,721 字节**，SHA-256 为 `92b1a5d7faf5079a5d0ab6593bd62334d1704b25b4031c68a5c2476be7ef73b8`。实际内容由发布清单的 `buildId` 和哈希确定；旧库会通过安装器切换到新一代。

本次仅本地提交，没有推送或部署。维护者只需推送插件仓库，无需推送根工作区迁移清单到插件仓库。缺失或损坏的内置包会报错并保留旧库，可重新更新完整插件，或配置相同内容的 HTTPS 镜像后重载并执行 `/rtlink library retry`。

未来更新数据时，同时提交新的 ZIP 与清单中的 archiveFile、buildId、大小和哈希。离线迁移也可以关闭自动安装，将 ZIP 中的 `chart_library` 完整目录放入持久化目录，保留已有版本并核对指针和哈希。

```text
chart_library/
  current.json
  versions/<buildId>/
    analysis.sqlite3   # 按曲名、别名、歌曲 ID 和谱面 key 查询；每谱独立压缩
    tja.zip            # 所有原始 TJA，包括暂时无法解析的原谱；没有音频
    sources.json       # 原始 TJA 路径及逐文件 SHA-256
    manifest.json     # ESE 提交、输入哈希、解析算法版本、文件哈希与覆盖数量
```

首次查询校验当前版本数据库 SHA-256，之后直接使用索引，只解压所需谱面。最多缓存 8 张谱面的结果；磁盘读取在线程中运行，不阻塞 AstrBot 事件循环。每次查询检查小型版本指针，新版本切换时清空旧缓存。

同名谱面不会互相覆盖。原文件含重复的 Oni/Edit 区块时以 `courseOccurrence` 区分，并标记 `duplicate-course-block`。普通/玄人/达人分歧存于同一份分析的不同路线中；缺失路线发生回退时保留警告。当前只分析单人鬼/里，其他难度和双人谱的原始文件仍随 TJA 包保存。

## 内部完整分析接口（不向 AI 注册）

`get_chart_analysis`：

| 参数 | 含义 |
| --- | --- |
| `song_name` | 曲名、内置别名、歌曲 ID 或查询返回的 `ese:<chartKey>`；支持难度前缀 |
| `level` | 鬼/4 或里/5；省略且存在多个难度时返回候选 |
| `route` | `N`/普通、`E`/玄人、`M`/达人或 `single`；默认使用整曲特征对应路线，并在结果中明确标记 |
| `detail` | `summary` 默认摘要及突出小节；`segments` 逐小节参数；`features` 整曲原始特征 |
| `start_measure`, `end_measure` | 小节范围，1 起算且包含结束小节，0 表示不限，仅用于 `segments` |
| `offset`, `limit` | 分页偏移与条数，默认 0/8；单次最多 20 条，按 `nextOffset` 翻页 |

示例：

```json
{"song_name":"天竺2000","level":"鬼"}
{"song_name":"天竺2000","level":"鬼","detail":"segments","start_measure":40,"end_measure":48}
{"song_name":"天竺2000","level":"鬼","detail":"features","offset":0,"limit":20}
```

返回 `ambiguous` 时使用候选 `chartKey` 消歧，不能自行选择同名变体。没有经过当前 RTLink 曲库映射复核的 ESE 谱面显示 `ESE-only`；不能把它直接当作对应国服街机谱面。曲名匹配沿用现有归一化规则和构建时的内置别名，不将用户输入当文件路径。

玩家与未玩歌曲的适配度由 `recommend_practice(goal="explore")` 一次筛选并返回配置依据、已玩参考曲和限制；单曲使用 `query_song_brief`。不再引导 AI 分别查画像、弱项、相似曲和逐小节数据。谱面的密度、间隔等原始参数与玩家能力分数不是同一量纲，不能直接相减得到“胜率”或精度预测。

## 参数语义与边界

- 整曲原始特征来自现有 parser-v5 索引，不加载模型权重；只对应 `featureRoute`，不能当成其他分歧路线的特征。
- 分段以小节为单位，保留起止时间、普通音符数量、平均/2 秒峰值密度、最短间隔、等效 16 分 BPM、节奏细分、配色切换、常见三连配色、连续击打、前 10 秒音符量、变速与滚动状态、黄条时长及气球要求。
- 时间原点是 `#START`，**不是音频播放时间**。OFFSET 只作为元数据保存，未自动转换为音乐时间戳。
- 密度只计击打音符，黄条/风船不混入密度；2 秒窗口是半开区间。连续击打明确采用相邻间隔不超过 250 ms 的统计定义，不代表训练后的体力难度评分。
- `maxTapFreeSeconds` 是没有普通击打音符的时间，可能仍有连打，不能直接称为休息时长。`preceding10sNotes` 是前序击打数量，不是生理疲劳模型。
- `topTriplets` 是相邻且总跨度不超过 0.5 秒的重叠三元组，`d/k/b` 分别为咚/咔/双色。单小节统计可能切断跨小节长串；整曲连续击打参数和相邻窗口保留额外参考。
- `hotspots` 分别选择密度、连续击打时长、配色切换最多的几个小节。它们是指标突出区间，**不是经过标注验证的综合难度排名，也不保证囊括全部主观难点**。
- 负 DELAY 会导致时间轴不单调：返回 `timeReliable=false`，相关时间指标留空，停止推荐突出区间。不支持的视觉命令、气球值缺失、连打结构异常及路线回退均保留警告。
- 当前 API 仅有玩家整曲成绩，不能定位玩家在哪个小节失误。本工具提供公共参考，不宣称任何玩家已具备或不具备某段能力。

## 离线构建与更新

2026-10-15.1 游戏谱面绑定为 1,577（原映射 1,344 + 补充 233），较前一版增加 15 个；
分析总量仍为 3,255。补充绑定按具体 ID/难度检查独立来源完整曲名、星级、物量、唯一 ESE 源谱和指纹，
不会因为该歌已有评级就漏掉其他难度。评级资源本身未改。完整来源、272 个待绑定身份和
来源差异见 [全量对应表](song-mapping-audit-2026-10-15.html)及[审核说明](song-aliases.md)。

在插件目录执行，使用已有数据维护流程生成的 **同一 ESE 提交**的 parser-v5 索引和已复核映射：

```powershell
python scripts/build_chart_library.py `
  --ese-root <ESE目录> `
  --index <parser-v5/ese-index.v1.json> `
  --mapping <parser-v5/mapping-report.v1.json> `
  --output <插件持久化数据目录/chart_library> `
  --quota-mib 512
```

构建器检查 ESE Git 提交、TJA 工作区改动、谱面指纹映射及原谱音符数。原谱完整归档；每个分析结果记录源文件哈希。相同原谱、整曲索引行和构建算法哈希可以复用压缩结果；变更项重新解析。SQLite 完整性校验成功后才原子切换 `current.json`。

旧版本目录始终保留，作为可回退备份。构建失败不会更换当前指针，失败的构建暂存版本也保留供检查。离线构建器默认 512 MiB 配额包含旧版本，构建前至少预留 64 MiB 配额空间及 256 MiB 磁盘空间。该配额独立于成绩数据库配额；`/rtlink storage` 展示当前分析库大小，不会自动删除谱面库或旧版本。运行时查询不产生分析副本。

手工迁移时先复制完整新版本目录，核对 `manifest.json` 的文件哈希，最后切换 `current.json`；不要仅复制数据库或先切换指针。手工回退前关闭自动安装并重载插件，再将指针改为已保存的旧 `buildId`，避免后台再次更新。旧版本若与当前歌曲目录哈希不符，工具会拒绝混用。

时间轴提取实现改编自 Taiko Trace 的 `taiko_model/tja_features.py` 维护快照，原文件 SHA-256 见 `scripts/tja_timeline.py` 文件头；现有外部解析器、评级模型与训练数据均未修改。
