## 回归验证

全量回归通过 294 项。之后补齐 Sakura 证据行曲名，相关来源、命令、配置历史和图片测试通过 22 项；再增加实际插件初始化检查，最终多来源专项通过 8 项。专项覆盖：

- 同一 QQ、玩家 ID、曲目 ID，在两个独立 SQLite 中保存不同成绩，绑定、缓存与历史互不改写。
- 切换和解绑只影响当前来源；重建路由器保留来源选择，重新打开 SQLite 保留历史。
- 相同成绩不重复生成评级快照，变化只追加到对应来源历史。
- token 失效、响应格式错误或玩家 ID 改变时，不替换已有成绩与缓存。
- 同用户同步期间来源切换排队；普通查询使用当前来源的缓存。
- 真实命令入口拒绝群聊绑定 token，正确分发私聊绑定与来源切换。
- 仅绑定 Sakura 的用户也能申请和使用共享歌曲别名。
- 实际插件初始化保留旧 `bindings` 键与根目录数据库，另建 Sakura 绑定键和数据库。
- 客户端使用固定 POST 地址，不跟随重定向，不回显包含 token 的远端错误体。

修改后的 Python 源码通过 AST 解析，配置 JSON、Git diff 空白检查通过；提交范围检查未发现真实测试 token。测试依赖隔离安装在被忽略的 `data/test-runtime/`，未改变项目依赖声明。

这验证了真实 Sakura API、本地服务和渲染，以及使用 mock AstrBot 的命令与初始化流程；未在真实 AstrBot / OneBot / QQ 环境部署或收发验证。
