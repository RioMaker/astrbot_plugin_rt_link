## 来源与优先级

| 来源 | 作用 |
| --- | --- |
| [Sakura 公共曲库](https://viewer.sakura-bot.cn/api/content/songs) | 当前国服显示名、日文、游戏 ID、难度、可用时的物量及状态 |
| [菌菌公共曲库](https://kinoko.zorua.cn/api/scores/catalog?schema_version=3) | 以 `game_id` 连接；`kinoko_id` 只作来源身份，不作歌曲 ID |
| `resource/charts.v1.json.gz` | 保留既有国服名称、评级谱面身份及物量 |
| [ESE TJA](https://ese.tjadataba.se/ESE/ESE.git) | 已核对映射的 TITLE/TITLEJA，含罗马字与英文写法 |
| 段位资料、人工表 | 课题曲写法、明确短名、旧罗马字名；口语别名保留人工来源标签 |

显示优先级为当前国服名 → 既有国服名 → 来源曲名。下架曲保留既有国服译名，另收录归档中的罗马字，避免把原中文名称覆盖掉。未确认国服收录的曲目标为“未确认”，不自动当成国服新曲。

`scripts/data/song_names.json` 保存公开来源精简快照与 SHA-256。143 个只见于 Sakura“其他歌曲”栏的站内编号被排除，没有作为游戏 ID 进入运行资源。来源之间的 23 处归一化后仍不同的写法按同一 `game_id` 复核，包括长短标题、繁简体、作品副题和异变标点；不抹去版本信息。

## 归一化与运行时

`NFKC → 大小写折叠 → 片假名折平假名 → 常见繁简折算 → 去空白标点`。纯符号曲名（例如 `+♂`）用稳定的字母数字键保留，不再归一化为空。大小写、全半角、空格和常见标点不必逐条手写别名。

`names` 的首项始终是优先展示名；`aliases` 收录其他写法；`name_sources` 保存每个写法的来源；`metadata` 保存物量、星级及是否进入评级曲库。`song_alias` 供段位、成绩搜索和别名申请共用。公共分析包构建时同样导入此表；别名更新后需重建数据包。

## 可重现维护

公开原始下载保存在本地 `cache/alias-audit/`，不随插件发布。仓库内已有精简快照，因此日常重建不必联网，也不会因缺少 ESE 路径丢掉已有罗马字名称：

```powershell
python scripts/build_dan_courses.py
python scripts/build_aliases.py
python scripts/audit_song_aliases.py
```

更新公开来源时，先下载匿名公开曲库，再生成新快照并审核差异：

```powershell
python scripts/build_song_names.py --sakura <Sakura公开JSON> --kinoko <菌菌公开JSON> --ese-root <ESE目录> --mapping <已审核mapping-report.v1.json> --index <同版本ese-index.v1.json>
```

ESE 补充绑定要求独立来源完整曲名、难度、星级、物量及唯一源谱，保留指纹；当前在原 1,344 条映射外有 233 条补充绑定，共 1,577 条。原有同名变体待复核项不强行匹配。更新后需依次重建别名和内置分析包，再运行全量审核：

```powershell
python scripts/audit_song_mapping.py --sakura <Sakura公开JSON> --kinoko <菌菌公开JSON> --index <ese-index.v1.json> --library <已构建chart_library目录> --score-snapshot <可选的本地成绩快照>
```

`--score-snapshot` 可以省略；输入不含凭据且不会复制到报告。输出默认是 `docs/song-mapping-audit-2026-10-15.html/.json`，可用 `--output` 指定新日期。全量审核会拒绝旧别名包、孤立绑定、难度/物量错误、缺少独立源名和遗漏的唯一可确认绑定；来源值不一致则保留到审核项中。

验证：316 项测试通过；新内置包离线安装 `downloadedBytes=0`；1,577 个 ID/难度绑定及 3,255 个谱面键逐一查询成功，3,095 份归档 TJA 原始字节 SHA-256 一致。两首十段以 ID/国服/日文/罗马字/短名均可查，模糊 `Likelihood` 返回歧义。评级资源 SHA-256 未变。
