# 曲名与别名索引

同一首歌在不同资料里叫法完全不同，段位查询、查分、别名申请要是各写一套匹配逻辑，
就会出现「同一次提问在 A 处查得到、B 处查不到」。本文记录插件统一的别名索引：
数据从哪来、怎么构建、怎么匹配、怎么维护。

---

## 1. 为什么需要

| 场景 | 实际写法 | 例子 |
| --- | --- | --- |
| 国服（菌菌）曲名 | 中文 / 英文 / 罗马字，取决于国服本地化 | `北埼玉2000`、`Dragon Night`、`Re ： End of a Dream` |
| 日文曲名 | 段位资料、wiki 用的写法 | `きたさいたま2000`、`第六天魔王` |
| 罗马字 / 英文 | ESE（TJADB）谱面 `TITLE:` 字段 | `Kita Saitama 2000` |
| 玩家口语 | 简称、黑话、常见错写 | `北埼玉`、`六天`、`罗特`、`顿卡马`、`天狗` |

段位资料里 456 条课题曲记录（2022–2026 五届日版/国际版 + 国服 2023/2024/2025）中，
只有 144 条的字面写法与曲库国服曲名完全相同、282 条是日文写法、19 条要靠归一化或别名才能对上，
其余 11 条（3 首旧曲 + 8 首 2026 新曲）尚未进入评级曲库。
也就是说：玩家直接用国服曲名去问段位，**超过六成会查不到** —— 这正是别名索引要解决的问题。

统计口径见 `scripts/survey_dan_coverage.py`（逐个课题曲记录比对段位写法与曲库 `title`/`titleJa`），
换段位资料后重跑即可刷新上面这组数字。

## 2. 归一化与匹配规则

```
归一化 key = NFKC → 大小写折叠 → 片假名折平假名 → 繁简折算 → 去掉空白与标点
```

- 片假名折成平假名：`ドンカマ2000` 与 `どんかま2000` 落到同一个 key。
- 繁简/异体折算：`雙龍ノ亂` = `双竜ノ乱`、`黃ダルマ2000` = `黄ダルマ2000`、`中國大陸` = `中国大陆`。
  国服曲名里也常混入日文字形（`天体観測`、`幕末維新譚`），因此日文新字体同样折算成简体
  （`観→观`、`測→测`、`戦→战`…），简中输入也能命中。
- 只保留中日文与字母数字，因此 `Re：End of a Dream`、`re end of a dream`、`reendofadream` 等价。

匹配优先级（`song_alias.resolve`）：

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| `exact` | 归一化后完全相等 | `北埼玉2000` → 338 |
| `prefix` | 一方是另一方的前缀 | `北埼玉` → 252／338 |
| `contains` | 一方包含另一方 | `天狗` → 天狗囃子／天狗配乐 等 |

同级之间按「请求的难度优先 → 难度序号 → 曲目 ID」排序，结果里同一首歌只保留一条
（`level` 参数用于挑选要展示的难度）。指向多首歌时**不猜**：调用方要么把候选都列出来
（段位查询），要么请用户用更精确的名字或 ID（别名申请）。

## 3. 数据来源

| 来源 | 内容 | 覆盖 |
| --- | --- | --- |
| `resource/charts.v1.json.gz` | 国服曲名（`title`）+ 日文曲名（`titleJa`） | 1393 / 1393 |
| ESE（TJADB）TJA `TITLE:` | 罗马字 / 英文曲名 | 880 |
| `resource/dan_courses.v1.json.gz` | 段位资料里的写法（多为日文） | 8 条为段位独有写法 |
| `scripts/data/song_aliases.json` | 人工整理的简称、黑话、常见错写 | 371 条（约 137 首曲目） |

派生写法（构建时自动生成，让「少打几个字」也能查到）：

- 去掉 `【限定】`、`（…）`、`（裏譜面）` 等括号内容；
- 只取 `～` / `~` 之前的主标题；
- 去掉 `2000` / `200` 尾缀（`北埼玉2000` → `北埼玉`）；
- 去掉空格与符号的紧凑写法（`Rotter Tarmination` → `rottertarmination`）。

## 4. 构建

```powershell
python scripts/build_aliases.py `
  --ese-root "<ESE 根目录>" `
  --mapping "<rating 工程的 mapping-report.v1.json>"
```

产物：

| 文件 | 内容 |
| --- | --- |
| `resource/aliases.v1.json.gz` | 每个 `song_no\|level` 的 `names`（规范名）与 `aliases`（别名） |
| `resource/aliases.manifest.json` | 版本、各来源条数、平均写法数、冲突写法（同一写法指向多首歌） |

当前构建结果：1393 张谱面 / 5509 条写法（平均 3.95 条每张）/ 49 个冲突写法。

不传 `--ese-root` 与 `--mapping` 也能构建，只是缺少罗马字曲名（离线或没有 ESE 时使用）。

构建顺序：段位资料更新后（`scripts/build_dan_courses.py`）**必须重跑本脚本**，
否则新一届课题曲的写法（例如 2026 届的 `鈍響ライクリフド`）不会进入别名表。
输出用固定 gzip mtime，相同输入重复构建的字节完全一致，便于比对提交。

## 5. 运行期怎么用

| 入口 | 用法 |
| --- | --- |
| `/rtlink dan [年份] [段位] [曲名]`、`/rtlink 段位 …` | 段位课题曲查询；曲名支持别名，可写「鬼 天竺2000」限难度 |
| `/rtlink score <曲名\|别名>` | 单曲成绩查询；别名命中后按曲目 ID 取成绩 |
| `/rtlink alias <曲名或ID> <别名>` | 别名申请；解析阶段同样走别名索引，歧义时提示候选 |
| LLM 工具 `query_dan_course` / `search_scores` | 与命令共用同一张索引 |
| `get_improvement_candidates` 等文本工具 | 曲名展示保持国服名为准 |

查询结果的展示统一为「《国服名》（日文名）」+ RTLink 曲目 ID，
段位课题曲还会带上难度与星级（`鬼★10`、`里★10`），方便直接接着 `/rtlink score <ID>` 查成绩。

## 6. 维护

1. **加别名**：编辑 [`scripts/data/song_aliases.json`](../scripts/data/song_aliases.json)，
   键是曲目 ID，值是别名数组，然后重跑 `scripts/build_aliases.py`。
   构建脚本会校验 ID 是否存在（不存在的会打印出来并忽略）。
2. **加完自检**：重跑 `python -m pytest test/test_song_alias.py -q`；
   里面的参数化用例会验证一批已知别名（北埼玉、六天、罗特、顿卡马…）指向正确曲目。
3. **别写重复别名**：能被前缀/包含匹配命中的写法不用登记
   （「北埼玉」之于「北埼玉2000」已由派生规则覆盖，只有「六天 → 第六天魔王」这种
   字面无关的简称才需要人工登记）。
4. **留意冲突**：manifest 里的 `ambiguousKeys` 会列出指向多首歌的写法。
   多数是同曲的表/里或双打版本（正常），若是真正写错就需要修正。
5. **用户别名**：`/rtlink alias` 提交、管理员 `/rtlink aliasapprove` 通过后写入 SQLite，
   运行期优先级高于内置别名（内置索引打底、用户别名覆盖）。
